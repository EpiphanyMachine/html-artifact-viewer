Status: Live-use evaluation · Author: Greg Hilkert, with Codex · Engineering: Greg Hilkert

Turn standalone HTML stored in GitHub into a page you can read and use, through the Raw link you already have.

For people sharing generated PRDs, prototypes, reports, and small tools. Today, viewing one means downloading it or setting up another place to host it. The viewer lets the browser render the file it already receives, for repositories the reader explicitly chooses.

This document is also the test artifact: its styles, embedded image, section links, theme control, and repository simulator all travel in this one file. It works offline and inside the viewer’s sandbox.

Success in this version

A reader loads the extension, adds the right repository, clicks Raw, and uses a standalone artifact without a clone, server, or additional login.

Scope

GitHub’s raw host on desktop Chromium 120+. The name leaves room for other hosts; GitLab, Bitbucket, Firefox, Safari, and mobile support are not implemented.

Product contract

Requirements you can verify

These describe the v0.2 implementation. Each ID is a stable section link for design discussions and verification.

REQ-1

Render only selected repositories

Start with an empty list. Accept explicit owner/repository entries or plain GitHub repository URLs, normalize duplicates, and support up to 100 repositories.

Verify: an unlisted repository stays as source. Adding it and reloading enables rendering. Wildcards and file URLs are rejected without replacing the saved configuration.

REQ-2

Keep GitHub’s existing Raw action

Render top-level .html and .htm responses from raw.githubusercontent.com. Keep GitHub’s repository interface unchanged.

Verify: click Raw on an allowed HTML file; the page renders. Non-HTML files and similarly named repositories stay unchanged. Section anchors remain usable.

REQ-3

Make the artifact interactive and self-contained

Support inline styles and embedded images, fonts, and media by default. Inline scripts require explicit trust for each repository; scripts start disabled. A portable file must carry its own essential assets.

Verify: explicitly enable scripts for this repository, then switch the comparison above, change the theme, and use the simulator below. The embedded blue icon appears. Save this file using the browser’s Save Page As command and repeat offline; the local copy is outside the extension’s sandbox and script settings.

REQ-4

Keep extension data local

Store only repository settings, explicit script opt-ins, and the enabled flag in this browser profile. The extension changes response headers without reading, storing, or uploading HTML bodies.

Verify: saved settings contain no file URLs or temporary access tokens. The runtime has no network client, remote code, or telemetry.

REQ-5

Pause without losing the list

Save an enabled or paused state alongside the repository list. Settings and rendering rules survive browser restarts.

Verify: pause, save, and reload a raw file; it returns to source. Resume, save, and reload to render again. Restart the browser and confirm the saved behavior.

REQ-6

Use the reader’s existing GitHub access

Require no extension authentication. Render private files only when GitHub already lets the browser retrieve them.

Verify: open a private artifact through GitHub using your own session. Access errors stay errors; the extension grants no new access. Reopen expired raw links through GitHub.

REQ-7

Keep scripts off until each repository is explicitly trusted

Adding a repository enables rendering only. Inline scripts start off, including for repositories retained during an upgrade from v0.1. Offer a separate script checkbox for each configured repository, with a warning that scripts can transmit document contents and private raw URL tokens through navigation. Trust covers every matching file, branch, and revision in that repository.

Verify: a newly added repository renders without running scripts. Opting in enables scripts only for that repository after reloading. Revoking trust disables them on reload. Removing and re-adding a repository does not restore its prior script permission.

REQ-8

Block artifact downloads in both modes

Do not offer a download setting. Block automatic downloads, download links, and exports triggered by a user click, including “Download CSV” buttons. Enabling scripts does not grant download permission. The browser’s own Save Page As command is separate from an artifact export.

Verify: neither a script running on load nor a clicked export button can download a file, even in a repository explicitly trusted to run scripts. Download support is out of scope until a concrete use case is established.

UX & interaction

One setup surface. One familiar action.

  1. Load the unpacked extension. Enable Developer mode in the browser’s extension manager and select the extension/ folder.
  2. Choose repositories in Options. One per line; plain GitHub repository URLs also work. Scripts stay off unless you explicitly enable them for that repository. Save before opening the artifact.
  3. Open the GitHub file and click Raw. For a matching repository, the browser renders the page automatically.

Why reuse Raw?

It already belongs to GitHub’s file workflow. No injected button, renamed control, or dependency on GitHub’s page layout is needed.

What readers need to know

Rendering is tied to the file’s repository, not to where the extension’s code lives. A saved change applies on the next raw-file load.

Privacy & boundaries

The browser receives the file. The extension supplies the rule.

Browser requests raw HTML→Browser applies repository rule→Browser renders isolated page

The extension uses declarative response-header rules. There is no preview backend or HTML processing service. Normal GitHub requests and browser history still exist. Script opt-ins are stored locally. Upgrading from v0.1 turns scripts off; reload existing artifacts to apply the policy.

Available in the preview

  • Inline CSS; JavaScript only for explicitly trusted repositories
  • Embedded data and blob assets
  • Section links and local interaction

Unavailable in the preview

  • External assets, scripts, and frames
  • Fetch/XHR and form submissions
  • Cookies and normal browser storage
  • Extension API access
  • All artifact downloads, including clicked export buttons and download links

Scripts are off by default. Enabling them trusts every matching file and revision in that repository: scripts can send the current document and its private raw URL token to another site by navigating the tab. Scripts-off is not a guarantee of zero network requests; links can still navigate. This is a portable-document viewer, not a malware-analysis tool or a development server for multi-file applications.

Live verification

Test the viewer with its own brief

  1. Load the repository’s extension/ folder unpacked. If it is already loaded, click Reload in the extension manager after code changes.
  2. In extension Options, add EpiphanyMachine/html-artifact-viewer. Leave its script checkbox off and save to verify the default behavior.
  3. Open this file on GitHub and click Raw. You should see this designed page rather than its source, but its script-driven controls should be inactive.
  4. In Options, read the trust warning and explicitly enable scripts for this repository, save, and reload the Raw tab. This does not enable downloads.
  5. Switch Source / Rendered, change the theme, and use the repository simulator. These verify inline JavaScript and styles.
  6. Follow REQ-3 to verify a section anchor, then resize to a narrow window. The page should remain readable without horizontal scrolling.
  7. Use the browser’s Save Page As command to save the HTML file and open it offline. Its content and controls should still work; the local copy is outside the extension’s sandbox and script settings.
  8. Pause previews in extension Options, save, and reload the Raw tab. Source returns. Resume, save, and reload to restore this page.

Share the normal GitHub file URL. Avoid sharing private Raw URLs containing temporary access tokens.
